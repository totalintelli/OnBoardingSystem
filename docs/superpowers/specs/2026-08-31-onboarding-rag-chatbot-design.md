# 신입사원 온보딩 규정 안내 챗봇 — 설계 스펙

## 배경 및 목적

기업 신입 직원이 사내 내규·업무 규정을 질문하면, 관련 규정 문서를 검색해 근거 기반으로 답변하는 챗봇 프로토타입. 채용 과제(면접용) 프로토타입으로, 완성된 상용 서비스가 아니라 핵심 기능과 서비스 가치를 보여주는 데 집중한다.

실제 회사 데이터는 없으므로 AI로 더미 규정 문서를 생성해 사용한다.

## 범위

- **포함**: 사내 규정 문서 기반 질의응답, 출처 문서 표시, 모르는 질문에 대한 안전한 fallback.
- **제외**: 계정 발급/권한 프로비저닝, 교육 진행 추적, 체크리스트 관리 등 온보딩의 다른 서브시스템. (README의 "내규·업무 규정 안내"에 집중)

## 우선순위

동작하는 데모를 빠르게 완성하는 것이 최우선. 모델 조합은 표준적인 선택지로 바로 확정하고, 조사에 시간을 쓰지 않는다.

## 아키텍처

```
data/docs/*.md (더미 규정 문서)
        │
        ▼
   rag.py (문서 청크 분할 → 임베딩 → 코사인 유사도 검색)
        │  top-k chunk + 유사도 점수
        ▼
   llm.py (로컬 소형 LLM, 검색 결과를 컨텍스트로 답변 생성)
        │  답변 + 참조 문서 목록
        ▼
   app.py (Streamlit 채팅 UI, 답변 아래 출처 표시)
```

### 컴포넌트

**data/docs/*.md**
AI로 생성하는 더미 사내 규정 문서 6~8개. 예: 연차/휴가 규정, 근태 규정, 경비 처리 규정, 재택근무 규정, 보안 수칙, 복리후생 안내. 각 문서는 실제 신입사원이 물을 법한 구체적 수치(연차 일수, 경비 한도 등)를 포함해 데모 질문에 답할 근거가 되도록 작성.

**rag.py**
- 문서를 문단/섹션 단위로 청크 분할
- `sentence-transformers`의 다국어 소형 모델(`paraphrase-multilingual-MiniLM-L12-v2`)로 청크 임베딩, 앱 시작 시 1회 계산 후 메모리 유지
- 질문 임베딩과 numpy 코사인 유사도로 top-k(예: 3) 청크 검색
- 문서 수가 적어(수십 청크 수준) FAISS 등 벡터 DB는 불필요 — numpy 배열 전수 비교로 충분

**llm.py**
- `transformers`로 로컬 소형 생성 모델(`Qwen2.5-1.5B-Instruct`, CPU 추론 가능, API 토큰 불필요) 로드
- 검색된 청크를 컨텍스트로 넣은 프롬프트로 답변 생성
- 최고 유사도 점수가 임계값 미만이면 LLM 호출 없이 "문서에서 확인되지 않음, 인사팀 문의" 고정 응답 반환 (환각 방지)

**app.py**
- Streamlit 채팅 인터페이스
- 답변 아래에 실제로 참조한 문서 파일명을 출처로 표시 (RAG 구조를 시각적으로 증명)

## 에러 처리

- 검색 결과 유사도가 임계값 미만: LLM 호출 생략, 고정 fallback 메시지로 응답하고 담당 부서 문의 안내
- 모델 로딩 실패 등 예외 상황은 프로토타입 범위에서 최소 처리(Streamlit 화면에 에러 노출)로 충분 — 별도 재시도/알림 로직 불필요

## 테스트

핵심 로직(검색 → 컨텍스트 구성 → fallback 판단)에 대해 `assert` 기반 자체 점검 스크립트 1개로 충분. UI는 수동 데모로 확인.

## 명시적으로 하지 않는 것

- 사용자 인증/권한 관리
- 대화 이력 영속 저장(DB)
- 다국어 UI, 다중 세션 관리
- 문서 관리자 편집 UI
